# User Personas and Use Cases for PrintNet
Author: Mo Al-Khasawneh (alkhasmr)  
Course: CS 5001 – Senior Design

## 1. Overview
This document outlines who will use PrintNet and how they are expected to interact with the system.  
The goal is to translate high-level ideas into concrete user personas and typical use cases.

Some details are based on common practices in university 3D printing labs and may need validation with UC lab staff later.

## 2. Personas

### Beginner Student
Goals:
- Submit a print with minimal steps
- Get feedback on printability
- Track status easily

Pain Points:
- Confusing slicer options
- Unsure which printer/material to select

### Advanced Student
Goals:
- More control over print settings
- Reuse previous jobs
- Review print history

Pain Points:
- Re-entering configuration
- Tracking which printer works best

### Lab Manager / TA
Goals:
- Monitor all printers and jobs
- Adjust queues and assignments
- Track usage for reporting

Pain Points:
- Multiple disconnected tools (email, SD cards, spreadsheets)
- Hard to see who submitted what and when

## 3. Core Use Cases
UC-1: Student submits print  
UC-2: Student checks status  
UC-3: TA manages queue  
UC-4: Lab manager views metrics
